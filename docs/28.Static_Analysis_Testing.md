# => static analysis

verify code without execution
analyzing how code is written

# => static analysis testing tool:

- typescript
  ensure type consistency in the code
  ex: you can't pass string if function expects number

- eslint
  ESLint is a static code analysis tool for JavaScript and TypeScript.
  It helps you find bugs, enforce coding standards, and keep code consistent—before your code runs.
  Think of ESLint as a code quality guard that reviews your code while you write it.

  importance:

  ***
  - Catch bugs early
  - Enforce best practices
  - Keep a consistent code style across a team
  - Avoid common JavaScript/React mistakes
  - Improve code readability & maintainability

  examples:

  ***
  - Syntax errors
  - Logical problems
  - Code style rules
  - Unused variables
  - Best practices

  # tools:
  - eslint extension
  - @testing-library
  - eslint-plugin-jest-dom

- prettier
  consistent style for all outputted code
  good for team multiple developers
  => command
  => custom configuration if needed inside .prettierrc file
  => eslint-config-prettier: Turns off all rules that are unnecessary or might conflict with Prettier.

- husky
  is a tool to improve the commits
  npx husky init => create .husky folder with pre-commit hook
  run lint & formatter before commit

# can't commit unless solve the issues of lints & prettier

- lint-staged
  run lintets & formatters against staged git files

==> pre-commit hook -> lint-staged
==> pre-push hook -> npm test

## Husky v9 Note
`npx husky add` is deprecated in v9. To create a hook, just create a file in `.husky/`:
```bash
echo "npm test" > .husky/pre-push
```
