# queryBy Documentation

## Overview

`queryBy` queries are non-throwing variants of `getBy` queries. They return `null` instead of throwing an error when no matching element is found. This makes them perfect for testing the **absence** of elements in the DOM.

## Key Difference: getBy vs queryBy

### getBy - Throws on No Match
```javascript
// Throws an error if element doesn't exist
const button = screen.getByRole("button", { name: "Delete" });
// Error: Unable to find an accessible element with the role "button" and name "Delete"
```

### queryBy - Returns null on No Match
```javascript
// Returns null if element doesn't exist (no error thrown)
const button = screen.queryByRole("button", { name: "Delete" });
// button = null (no error)
```

## When to Use queryBy

Use `queryBy` when you want to:
- **Test that an element does NOT exist** in the document
- **Conditionally check** for elements without causing test failures
- **Assert absence** of elements based on component state

## Syntax

```javascript
queryByRole(role, options);
queryByText(text, options);
queryByLabelText(label, options);
queryByPlaceholderText(placeholder, options);
queryByAltText(alt, options);
queryByTitle(title, options);
queryByDisplayValue(value, options);
queryByTestId(testId, options);
```

## Return Value

- **Returns**: The matching element if found, or `null` if not found
- **Never throws**: Unlike `getBy`, `queryBy` never throws an error

## Examples

### Testing Element Absence

```javascript
import { render, screen } from "@testing-library/react";
import { Skills } from "./Skills";

test("start learning button is not rendered initially", () => {
  render(<Skills skills={["HTML", "CSS"]} />);
  
  // Use queryBy to check if element doesn't exist
  const startLearningButton = screen.queryByRole("button", { 
    name: "Start learning" 
  });
  
  // Assert that the button is NOT in the document
  expect(startLearningButton).not.toBeInTheDocument();
  // or
  expect(startLearningButton).toBeNull();
});
```

### Testing Element Presence

```javascript
test("login button is rendered initially", () => {
  render(<Skills skills={["HTML", "CSS"]} />);
  
  // queryBy can also be used to check presence
  const loginButton = screen.queryByRole("button", { name: "Login" });
  
  expect(loginButton).toBeInTheDocument();
});
```

### Conditional Testing

```javascript
test("error message appears conditionally", () => {
  const { rerender } = render(<Form hasError={false} />);
  
  // Initially, error message should not exist
  let errorMessage = screen.queryByText(/error/i);
  expect(errorMessage).not.toBeInTheDocument();
  
  // After rerender with error, it should exist
  rerender(<Form hasError={true} />);
  errorMessage = screen.queryByText(/error/i);
  expect(errorMessage).toBeInTheDocument();
});
```

## All queryBy Variants

Every `getBy` query has a corresponding `queryBy` variant:

| getBy Variant | queryBy Variant | Description |
|--------------|----------------|-------------|
| `getByRole` | `queryByRole` | Query by accessibility role |
| `getByText` | `queryByText` | Query by text content |
| `getByLabelText` | `queryByLabelText` | Query by label text |
| `getByPlaceholderText` | `queryByPlaceholderText` | Query by placeholder text |
| `getByAltText` | `queryByAltText` | Query by alt text |
| `getByTitle` | `queryByTitle` | Query by title attribute |
| `getByDisplayValue` | `queryByDisplayValue` | Query by display value |
| `getByTestId` | `queryByTestId` | Query by test ID |

## Common Patterns

### Pattern 1: Asserting Absence
```javascript
test("modal is closed initially", () => {
  render(<App />);
  
  const modal = screen.queryByRole("dialog");
  expect(modal).not.toBeInTheDocument();
});
```

### Pattern 2: Conditional Rendering Tests
```javascript
test("shows loading state", () => {
  render(<DataComponent isLoading={true} />);
  
  // Content should not be visible during loading
  const content = screen.queryByText("Data loaded");
  expect(content).not.toBeInTheDocument();
  
  // Loading indicator should be visible
  const loader = screen.queryByRole("status");
  expect(loader).toBeInTheDocument();
});
```

### Pattern 3: State-Based Visibility
```javascript
test("button visibility changes with state", () => {
  const { rerender } = render(<Component isLoggedIn={false} />);
  
  // Logout button should not exist when not logged in
  expect(screen.queryByRole("button", { name: "Logout" }))
    .not.toBeInTheDocument();
  
  // Login button should exist
  expect(screen.queryByRole("button", { name: "Login" }))
    .toBeInTheDocument();
  
  // After login
  rerender(<Component isLoggedIn={true} />);
  
  // Login button should not exist
  expect(screen.queryByRole("button", { name: "Login" }))
    .not.toBeInTheDocument();
  
  // Logout button should exist
  expect(screen.queryByRole("button", { name: "Logout" }))
    .toBeInTheDocument();
});
```

## Important Notes

### ⚠️ queryBy Still Throws on Multiple Matches

```javascript
// If multiple elements match, queryBy will still throw
const buttons = screen.queryByRole("button"); 
// Error: Found multiple elements with the role "button"

// Use queryAllByRole instead for multiple elements
const buttons = screen.queryAllByRole("button");
expect(buttons).toHaveLength(2);
```

### ✅ Use with toBeInTheDocument()

```javascript
// Good - clear assertion
expect(screen.queryByRole("button")).not.toBeInTheDocument();

// Also valid
expect(screen.queryByRole("button")).toBeNull();
```

### ❌ Don't Use queryBy for Required Elements

```javascript
// Bad - if element is required, use getBy
const submitButton = screen.queryByRole("button", { name: "Submit" });
submitButton.click(); // Error: Cannot read property 'click' of null

// Good - use getBy for required elements
const submitButton = screen.getByRole("button", { name: "Submit" });
submitButton.click(); // Works correctly
```

## Comparison Table

| Query Type | Returns | Throws on No Match | Throws on Multiple Matches | Use Case |
|-----------|---------|-------------------|---------------------------|----------|
| `getBy` | Element | ✅ Yes | ✅ Yes | Element must exist |
| `queryBy` | Element or `null` | ❌ No | ✅ Yes | Element may or may not exist |
| `getAllBy` | Array | ✅ Yes | ❌ No | Multiple elements expected |
| `queryAllBy` | Array | ❌ No | ❌ No | Zero or more elements |

## Best Practices

### 1. Use queryBy for Absence Tests
```javascript
// ✅ Good
test("error message is hidden", () => {
  render(<Form />);
  expect(screen.queryByText(/error/i)).not.toBeInTheDocument();
});

// ❌ Avoid - getBy will throw if element doesn't exist
test("error message is hidden", () => {
  render(<Form />);
  expect(() => screen.getByText(/error/i)).toThrow(); // More verbose
});
```

### 2. Use getBy for Required Elements
```javascript
// ✅ Good - element is required
const submitButton = screen.getByRole("button", { name: "Submit" });

// ❌ Avoid - queryBy returns null, which can cause issues
const submitButton = screen.queryByRole("button", { name: "Submit" });
if (submitButton) submitButton.click(); // Unnecessary null check
```

### 3. Combine with Conditional Logic
```javascript
test("handles optional elements", () => {
  render(<Component showOptional={false} />);
  
  const optionalElement = screen.queryByText("Optional content");
  
  if (optionalElement) {
    expect(optionalElement).toHaveClass("highlighted");
  } else {
    // Element is intentionally not rendered
    expect(optionalElement).toBeNull();
  }
});
```

```javascript

import { Skills } from "./Skills";

describe("Skills component", () => {
  const skills = ["HTML", "CSS", "JavaScript"];

  test("start learning button is not rendered initially", () => {

  });

```

## Related Queries

- **getBy** - Throws if element not found (use for required elements)
- **getAllBy** - Returns array, throws if none found
- **queryAllBy** - Returns array (empty if none found), never throws
- **findBy** - Async version that waits for element to appear
- **findAllBy** - Async version that waits for multiple elements

## Summary

- `queryBy` returns `null` instead of throwing when element is not found
- Perfect for testing element **absence**
- Still throws if **multiple** elements match (use `queryAllBy` instead)
- Use `getBy` for elements that **must** exist
- Use `queryBy` for elements that **may or may not** exist
